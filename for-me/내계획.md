# <문서의 용도> : 업데이트 시점

1. AGENTS.md : codex 작업 원칙, 위임 범위, 검증/기록 규칙, 개입 기록 트래킹

2. QUESTION.md : 담당자 질문 및 답변

- 내가 담당자 답변 받아서 codex에 전달
- 지시를 받은 codex(planner session)가 QUESTION.md에 정리

3. PLAN.md : 최종 목표, 수용 기준, 작업 분해, 설계 결정

- 나와 codex의 대화 및 담당자 답변 확보 후 내가 지시하는 경우에만 md에 정리
- R-01(Requirement, 검증 및 충족 여부 추적), T-01(Task, 어떻게 구현하는가?, Progress에서 상태 관리), D-01(Decision, 왜 이 방식을 택했나?, Defense에서 선택 근거 및 이해도 관리) 식별자를 정의하고, 다른 문서에서 이를 참조하는 방식으로 한다.

4. PROGRESS.md : 작업 상태, 실행 증거, 실패/수정 기록

- PLAN의 계획에 따라 개발 진행하면서 작업 상태 계속 업데이트 (codex dev session)

5. DEFENSE.md : 실제 구현 구조, 원리, 선택 근거, 리스크

- PROGRESS 업데이트 시점에 주요 결정 사항은 DEFENSE에도 반영

# <codex 명령 체계>

1. AUTO — Codex가 독립적으로 처리, 승인된 PLAN과 작업 범위 안에서는 계속 진행한다.

- 기존 구조를 유지하는 기능 구현
- 필요한 함수·모듈·테스트 파일 작성
- 테스트 실행 및 일반적인 버그 수정
- 오류 로그 분석과 원인 조사
- PROGRESS.md 갱신
- 중요 구현 내용을 DEFENSE.md에 기록
- 검증을 통과한 후 다음 Task 진행

2. ASK — 다음 상황에서만 내 판단을 요청

- 과제 목표·수용 기준·기능 범위를 변경해야 할 때
- 중요한 아키텍처·기술 스택을 선택하거나 변경할 때
- 업무 담당자에게 확인할 중요한 미해결 사항이 있을 때
- 기존 데이터 삭제·대규모 구조 변경 등이 필요할 때
- 실패한 작업을 기존 방식으로 해결하기 어려울 때
- 시간 부족으로 일부 필수 기능을 포기하거나 우선순위를 크게 조정해야 할 때

3. STOP — 반드시 막아야 할 작업

- API Key·토큰·비밀번호를 코드나 로그에 노출
- 문제·코드·결과물의 외부 전송 및 Git Push
- 공식 과제 파일의 무단 삭제·덮어쓰기
- 허용되지 않은 프로그램·외부 서비스 활용
- 테스트하지 않은 기능을 완료로 표시
