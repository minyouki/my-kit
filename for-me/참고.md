0. 과제 분석

```
너는 이번 과제의 계획 및 요구사항 분석 담당이야.

먼저 README.md, 공식 과제 안내, 프로젝트 구조와 기존 코드를 확인해 줘. AGENTS.md의 공통 규칙을 준수해.

아직 파일을 생성·수정하거나 코드를 구현하지 마.

다음 내용을 분석해서 보고해.

1. **과제 목표:** 해결해야 할 문제와 최종 산출물
2. **요구사항:** 필수 기능, 선택 기능, 각각의 완료 기준
3. **제출 조건:** 제출 형식·경로, 실행 환경, 시간·기술·보안 제약
4. **현재 상태:** 기존 프로젝트 구조, 재사용 가능한 코드와 설정, 확인이 필요한 부분
5. **불명확한 사항:** 요구사항의 모호함·충돌·누락
6. **담당자 질문:** 실제 구현에 영향을 주는 질문을 중요도순으로 제안
7. **초기 구현 방향:** 가능한 기술적 접근과 우선순위, 주요 위험

README에 명시된 사실과 네가 추정한 내용을 구분해 줘.

지금은 분석 단계이므로 PLAN.md도 아직 작성하지 마. 결과를 간결하고 구조적으로 보고한 뒤 내 다음 지시를 기다려.
```

0-1. 처음 보는 유형의 문제인 경우

README의 요구사항을 분석한 뒤, 바로 구현 계획을 작성하지 말고 먼저 해결 전략을 제안해 줘.

1. 문제를 입력·처리·출력으로 정의하고 독립적으로 검증 가능한 최소 단위로 분해해.
2. 각 단위가 일반 코드, LLM API, 외부 API, 데이터 저장, 머신러닝, 최적화 중 어떤 처리 방식에 적합한지 판단해. 사람의 승인이 필요한 부분은 별도로 구분해.
3. 가능한 해결 방법이 여러 가지라면 구현 난이도, 정확성, 실행 환경, 시간, 비용을 비교해 가장 단순하고 신뢰할 수 있는 방법을 추천해.
4. 선택한 방법들이 어떤 데이터와 인터페이스로 연결되는지 전체 솔루션 구조를 제시해.
5. 입력부터 출력까지 가장 먼저 실행할 최소 기능 경로를 정해.
6. 필수 기능별 성공 조건과 실패 가능성, 검증 방법을 제안해.
7. 요구사항에 명시된 사실, 네가 세운 가정, 내 판단이 필요한 사항을 구분해.

새로운 기술을 도입하기 전에 기존 프로젝트와 사용 가능한 라이브러리로 해결할 수 있는지 확인해.

아직 PLAN.md를 작성하거나 코드를 수정하지 말고, 해결 전략부터 보고해.
