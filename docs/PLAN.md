## 2. 요구사항 (R)

| ID  | 요구사항 | 수용 기준(실제로 확인할 동작·결과) | 검증 방법(실행 가능한 명령·조작) | 우선순위 | 근거 |
| --- | -------- | ---------------------------------- | -------------------------------- | -------- | ---- |

우선순위: `필수 / 선택` · 근거: `과제 안내 / 담당자 / 가정`. 미확정 내용은 가정으로 명시한다. 과제가 요구한 제출 문서·설정 파일도 R로 등록한다.

## 3. 실행 계획 (T)

| ID  | 관련 R | 작업 · 산출물 | 선행 T |
| --- | ------ | ------------- | ------ |

T 작성 지침:

- T는 가능하면 **사용자가 쓰는 기능 단위(수직 슬라이스)** 로 작성한다. 한 T는 DB → API → 화면까지 끝내고 실행해서 확인할 수 있는 단위로 자른다.
- 한 T가 너무 커서 중간 확인이 어려우면 더 쪼갠다.
- 각 T에 관련 R을 적고, 작업·산출물 칸에 무엇을 실행해 확인하는지 짧게 적는다.
- 환경 설정, 공통 검증, 문서·제출물처럼 기능 단위로 자를 수 없는 작업은 별도 T로 두고 그 이유를 한 줄로 적는다.
