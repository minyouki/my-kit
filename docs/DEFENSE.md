# DEFENSE — 구현 이해·후속 질문 준비

> 핵심 기능 완료·주요 결정·중요한 오류 해결 시 Dev가 갱신한다. **실제 코드와 검증된 사실만** 기록하고, 내 이해 여부는 내가 확인한다.

## 1. 전체 구조

- **해결한 문제:**
- **입력 → 처리 → 출력:**
- **핵심 파일·모듈(경로와 역할):**
- **실행·확인 방법:**

## 2. 핵심 동작

| 관련 R/T | 코드 위치(파일·함수) | 실제 동작 원리 | 확인 근거 | 내 이해 |
| -------- | -------------------- | -------------- | --------- | ------- |

내 이해: `설명 가능 / 재확인 필요`. 미검증 동작은 확인된 사실처럼 쓰지 않는다.

## 3. 주요 설계 판단

| D-ID | 선택 이유·대안과 차이 | 실제 적용 위치·검증 근거 | 남은 트레이드오프 |
| ---- | --------------------- | ------------------------ | ----------------- |

`PLAN.md`의 D-ID를 참조한다. 같은 결정의 상세한 경위는 반복하지 않는다.

## 4. 실패 조건과 한계

| 관련 R/T | 실패할 수 있는 조건 | 실제 처리·검증 상태 | 개선 방향 |
| -------- | ------------------- | ------------------- | --------- |

해당 시 빈 입력·외부 API 오류·타임아웃·동시 요청·브라우저 제약을 확인한다. 검증 상태는 `확인됨 / 미검증 / 미구현`으로 구분한다.

## 5. 내 이해도 점검

| 실제 코드 기반 예상 질문 | 내 답변 요지 | 확인할 파일·테스트 | 상태 |
| ------------------------ | ------------ | ------------------ | ---- |

Codex가 질문을 제안할 수 있지만, **내가 답하기 전에는 이해 완료로 표시하지 않는다.** 중요한 질문만 최대 3개 유지한다.
