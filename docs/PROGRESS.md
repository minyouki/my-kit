### 작성 규칙

- Dev는 작업명, 구현 내용·변경 파일·자체검증 결과를 기록한다.
- Test는 개발된 작업에 대해 독립 검증을 수행하고 검증 방법·실제 결과·증거를 기록한다.
- Dev는 자체검증 후 다음 작업을 진행할 수 있으며, 최종 완료는 Test PASS를 기준으로 한다.
- Test FAIL 시 Dev가 수정하고 Test가 동일 조건으로 재검증한다. 이전 실패·수정 이력은 보존한다.

- 계획 밖 작업은 `SUB-ID` 행으로 같은 표에 추가한다. PLAN에 필요한 것은 sub-dev가 `PLAN.md`에 직접 반영한다.
- `PLAN 반영`: `-`(PLAN 작업, 해당 없음) / `대기`(반영 여부 미결정) / `완료`(PLAN 갱신됨, 해당 ID 기재) / `불필요`(이유 기재). 최종 검증에서 `대기`가 남지 않게 한다.

**Test 판정:** `PASS / FAIL / NOT VERIFIED` (`-`는 아직 검증하지 않음을 의미)
